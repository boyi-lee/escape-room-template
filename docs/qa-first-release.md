# 第一版驗收報告

驗收對象：`feat/tetrabiblos-learning-site`

## 結論

目前狀態：**條件式不通過，暫不建議合併至 `main`**。

頁面已具備可展示的 MVP 外觀與基本互動，但在內容可追溯性、搜尋行為、學習解鎖邏輯、可維護性與無障礙方面仍有阻擋項目。

## 已通過

- 四書各有 4 個核心章節，共 16 章。
- 深藍／金色古典星盤視覺方向符合規格。
- 四書卡片、章節切換、完成標記、重置紀錄皆有對應程式邏輯。
- `localStorage` 可保存章節完成狀態。
- 12 題測驗具選項隨機排序、答題鎖定、正解提示與解析。
- 桌面、平板與手機有基本 RWD 斷點。
- 醫療、死亡、性別與地域內容有倫理與時代限制提示。

## 阻擋項目

### P0：內容缺乏原典定位

每章僅顯示「原典摘要」，沒有標示 Book／Chapter，也沒有提供來源頁碼或段落。使用者無法回到附件驗證內容，與「可驗證的知識網站」目標不符。

**修正要求：** 每章加入 `source` 欄位，至少標示「Book I, Chapter 4」等原典位置；高風險內容應補上版本／頁碼。

### P0：宣稱的解鎖流程未實作

首頁寫「最後以測驗解鎖學習進度」，測驗區寫「答對即記錄一枚星印」，但目前測驗結果沒有寫入任何進度，也不會解鎖章節。

**修正要求：** 二選一：
1. 實作測驗星印與章節解鎖；或
2. 移除所有「解鎖／星印」承諾，改成純自我檢核。

建議第一版採第 2 案，避免不必要複雜度。

### P1：搜尋只篩選整本書

輸入「婚姻」只會留下第四書，但不會定位到「婚姻、子女與人際」章節，也沒有顯示搜尋結果數或無結果狀態。

**修正要求：** 搜尋結果應直接列出匹配章節，點擊後開啟該章；無結果時顯示明確提示。

### P1：程式碼壓縮成少數超長行

`index.html` 幾乎全部壓在少數長行內，後續內容擴充、Code Review、Git diff 與除錯成本很高。

**修正要求：** 格式化 HTML／CSS／JavaScript；至少將資料、樣式與程式拆成 `data.js`、`styles.css`、`app.js`。

### P1：外部字體與 README 敘述矛盾

README 寫「無外部執行依賴」，但頁面依賴 Google Fonts。字體載入失敗不會破版，但此敘述不精確。

**修正要求：** 改成「無框架與後端依賴；字體使用 Google Fonts，失敗時回退系統字體」。

### P1：localStorage 缺乏容錯

若 `tetraDone` 被寫入非 JSON 內容，`JSON.parse` 會阻止整頁 JavaScript 執行。

**修正要求：** 使用 `try/catch` 與資料型別檢查，異常時回退空陣列。

## 建議改善

- 所有純操作按鈕補 `type="button"`。
- 搜尋欄補 `<label>` 或 `aria-label`。
- 卡片若可點擊，改為真正的 `<button>` 或加入鍵盤操作與語意。
- 補 `:focus-visible` 樣式。
- 支援 `prefers-reduced-motion`，關閉星盤旋轉與位移動畫。
- 測驗作答後補 `aria-live`，讓輔助工具讀出結果。
- 手機版目前直接隱藏導覽列，應改成簡化選單或保留核心導覽。
- 章節完成進度目前以 16 為硬編碼，應由資料自動計算。
